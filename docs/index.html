Giới thiệu

Vì sao cần skill này

Test do AI viết thường pass dễ dàng vì chúng được viết để pass. Skill này đặt mục tiêu ngược lại: tìm ra bug thật và dẫn chứng được bằng code.

Mỗi case đều có dẫn chứng

Mỗi test case trỏ tới đoạn code cụ thể (path:line). Không tìm được dẫn chứng thì case bị bỏ.

PASS lấy từ test runner

Trạng thái lấy từ JSON report của runner và được đối chiếu với todo, không dựa vào suy đoán.

Không làm test pass giả

Skill không nới assertion, không thêm .skip hay waitForTimeout, không nuốt lỗi và không sửa source để test pass.

Checklist 9 nhóm

Mỗi unit được xét theo 9 nhóm: input, quyền và trạng thái, lỗi từ dependency, đồng thời, toàn vẹn dữ liệu, thời gian/locale, bảo mật, UX/a11y và happy path.

Audit bảo mật

Theo dõi dữ liệu người dùng từ nơi đi vào (source) tới nơi sử dụng (sink) qua 13 nhóm lỗ hổng. Secret được che đi, skill không sửa code và không tấn công hệ thống nào.

Playwright khi bạn đồng ý

Skill hỏi trước khi làm việc với UI. Nó khảo sát DOM thật, dùng locator theo role và có sẵn công cụ ui-check.mjs.

Test phải biết fail

Với test P0, skill cố tình làm hỏng một bản sao của code để kiểm tra test có báo lỗi thật hay không.

Tiết kiệm token

Skill cache theo hash của source tree, nên file không thay đổi sẽ không bị đọc lại.

Chế độ repro

Viết đúng một test fail để tái hiện bug bạn báo. Skill chỉ sửa code khi bạn yêu cầu.

Cách dùng

Cách dùng cơ bản

/qa-test-agent                      # mặc định: code mới / vừa đổi
/qa-test-agent lite                 # cả project, chỉ P0, nhanh
/qa-test-agent full                 # cả project, sâu, P0–P3
/qa-test-agent audit                # quét lỗ hổng bảo mật (hoặc: audit <path>)
/qa-test-agent repro <bug hoặc issue>   # 1 test fail tái hiện bug

Với agent khác, bạn chỉ cần nhắn: “dùng skill qa-test-agent ở chế độ full”.

  1. Lần chạy đầu tiênSkill hỏi hai câu: có commit test được tạo vào git hay không, và có dùng Playwright cho frontend hay không. Câu trả lời được lưu trong .qa-agent/config.json.
  2. Xác nhận kế hoạchỞ chế độ full, skill cho biết tổng số case và hỏi bạn xác nhận trước khi ghi file.
  3. Đọc báo cáoBáo cáo gồm số liệu, các bug (kèm bước tái hiện và path:line), các case bị chặn và những rủi ro chưa được kiểm tra.

Công cụ kiểm tra UI

Công cụ này chạy độc lập, không cần agent (project cần cài sẵn Playwright). Nó mở trang ở các kích thước desktop, tablet và mobile, lưu aria snapshot và ảnh chụp, đồng thời đánh dấu lỗi console, request thất bại và các dấu hiệu lỗi a11y/layout.

Cách hoạt động

Quy trình tổng quan

Mỗi bước có một điều kiện kiểm tra; chưa đạt thì skill không chuyển sang bước sau.

  1. ScanHash source tree, chỉ đọc lại file đã đổi.
  2. Thiết kếChecklist 9 nhóm cho từng unit, thêm case cho guard còn thiếu.
  3. Evidence gateGrep từng path:line. Case không chứng minh được bị xóa.
  4. Viết testTheo convention của project, không sửa source.
  5. Chạy runner thậtĐọc JSON report, ánh xạ về TC-xxx.
  6. Báo cáoPASS chỉ khi runner xác nhận.

FAQ

Câu hỏi thường gặp

Skill có sửa source code của tôi không?

Không. Skill không sửa source để test pass, không tự cài package và không đổi config dùng chung khi chưa hỏi bạn. Nếu thiếu data-testid, nó chỉ đề xuất thêm.

Nếu code có vẻ bị bug thì sao?

Skill sẽ không viết test khẳng định một hành vi sai. Case đó được đánh dấu NEEDS-CONFIRM (nghi có bug). Lỗi đã được xác nhận thì báo là FAIL-PRODUCT, kèm bước tái hiện và path:line.

Hỗ trợ runner nào?

Skill theo convention sẵn có của project, ví dụ Vitest, Jest, Playwright hoặc runner khác mà nó nhận ra. Nếu project chưa có, skill đề xuất một runner và hỏi bạn trước khi cài.

Skill trả lời bằng ngôn ngữ nào?

Bản gốc của skill viết bằng tiếng Anh, nhưng skill trả lời theo ngôn ngữ bạn đang dùng. Ngoài ra có bản tiếng Việt đầy đủ trong docs/vi/.
